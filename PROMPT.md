# Промпт для Claude Code: PWA-трекер

Oct 14, 2026 · @Felix

## Задача

Ты строишь PWA-приложение «Трекер» для школьника или студента: оценки, финансы, расписание, заметки и график котировок криптовалют в одном приложении, которое работает офлайн и одинаково хорошо выглядит на телефоне и на ПК. Главное отличие продукта: строгий угловатый дизайн, который не похож на типовые интерфейсы с закруглениями и фиолетовыми градиентами.

Принципы:

- Все данные хранятся на устройстве, без бэкенда и регистрации. Единственный сетевой запрос в приложении: котировки криптовалют.
- Телефон и ПК: один код, две раскладки (порог 900 px).
- Интерфейс на русском. Код, имена переменных, коммиты и README на английском.
- Решения принимай сам, лишних вопросов не задавай. Каждое неочевидное решение записывай одной строкой в `DECISIONS.md`.
- Готовые библиотеки компонентов (MUI, Bootstrap, shadcn, Tailwind UI) не использовать: интерфейс рисуется своим CSS, иначе пропадёт характер.
- Данные в примерах ниже демонстрационные. В приложении при первом запуске пустое состояние с понятным действием, а не выдуманные оценки и деньги. Демо-данные включаются отдельной кнопкой в настройках.

## Стек и структура

Используй Vite, React 18 и TypeScript в строгом режиме, Dexie для IndexedDB, vite-plugin-pwa (Workbox) для офлайна и Vitest для тестов расчётов. Состояние интерфейса (вкладка, выбранный день, монета, период) держи в Zustand, а данные читай из Dexie через живые запросы. Графики рисуй вручную на SVG, библиотеки графиков не подключай. Стили: CSS-переменные и CSS Modules, без Tailwind. Роутер напиши сам на хэше (`#/grades`): экранов всего пять, react-router не нужен.

```
src/
  app/        Shell, навигация, хэш-роутер
  design/     tokens.css, base.css, компоненты: Panel, Stat, Chip, Segmented, Button, Field, Bar
  features/   grades, finance, schedule, notes, market, focus, overview
  db/         схема Dexie, миграции, экспорт и импорт
  lib/        форматирование чисел и дат, расчёты, клиент API котировок
  pwa/        регистрация service worker, кнопка установки
public/       manifest.webmanifest, иконки
```

Каждая фича содержит свои компоненты, хуки и тесты. Расчёты (средний балл, баланс, прогноз оценки, лимиты) выноси в чистые функции в `lib/` и покрывай тестами.

## Дизайн-система

Стиль: тёмный технический журнал. Прямые углы, толстые линии, один лаймовый акцент, крупные числа. Заложи это в `design/tokens.css` и во всём приложении используй только токены.

```css
:root {
  --ground: #101110;       /* фон */
  --panel: #171917;        /* выбранная строка, наведение */
  --line: #2B2E2A;         /* разделители */
  --line-strong: #3A3D38;  /* рамки блоков */
  --text: #ECE8DC;
  --text-soft: #B9B6AC;    /* текст заметок */
  --muted: #8C8F86;        /* подписи и метки капсом */
  --accent: #D7FF3D;       /* единственный акцент, текст на нём: --ground */
  --negative: #FF6A45;
  --radius: 0;
}
```

**Шрифты.** Oswald 500/600/700 капсом для заголовков и навигации, IBM Plex Sans 400/500 для текста, IBM Plex Mono 400/500 для чисел, дат и подписей. Все три с кириллицей. Подключи через `@fontsource`, чтобы они работали офлайн.

**Размеры.**

- Заголовок экрана: 46 px на телефоне, 104 px на ПК, Oswald 700, капсом, интерлиньяж 0.9.
- Заголовок панели: 34 px, Oswald 700.
- Метка: Plex Mono 11 px, межбуквенный интервал 0.1em, цвет `--muted`, капсом.
- Крупные числа: Plex Mono 500, 32–56 px. Средний балл: Oswald 700, 88–96 px, цвет `--accent`.
- Основной текст: 14–16 px.

**Правила формы.**

- `border-radius: 0` везде: кнопки, поля ввода, чекбоксы, полосы прокрутки, иконка приложения. Скруглений нет.
- Нет теней, градиентов, размытия и стеклянных панелей. Глубину дают только линии 1 px и 2 px.
- Блоки стыкуются рамкой 1 px с наложением на -1 px, как ячейки таблицы. Верх и низ экрана, шапка и нижняя навигация отделены линией 2 px цвета `--text`.
- Эмодзи и иконочных шрифтов нет. Вместо иконок: текстовые метки, индексы 01–05, квадратные маркеры. Если иконка нужна, рисуй inline-SVG прямыми линиями.
- Фиолетового нет ни в каком виде, акцент один.
- Рост и падение различай не только цветом: знак (+ и −), маркер (залитый квадрат для роста, пустой квадрат с рамкой для падения) и цвет вместе.
- Выбранный элемент инвертируется: фон `--text` и текст `--ground` (вкладки, периоды), либо фон `--accent` и текст `--ground` (день недели, главное действие).

**Движение.** Только резкое и короткое: 120 мс, без пружин и отскоков. Смена вкладки без перелёта, список появляется со сдвигом на 4 px. Уважай `prefers-reduced-motion`.

**Доступность.** Контраст текста не ниже 4.5:1, зона нажатия не меньше 44×44 px, заметный `:focus-visible` (2 px `--accent`), `aria-pressed` на переключателях, настоящие `button` и `a`, `lang="ru"`.

Под графиком максимум и минимум периода, затем список монет (BTC, ETH, SOL) с ценой и изменением за 24 часа, выбранная строка на фоне `--panel`.

### ПК

Слева боковая панель 240 px с линией 2 px справа: сверху ТРЕКЕР, ниже пять ссылок высотой 56 px (индекс и название), внизу дата и пометка про демо-данные. Справа шапка 72 px, заголовок обзора 104 px («СРЕДА.14» с лаймовой точкой) и полоса из четырёх показателей: средний балл, баланс, число уроков сегодня, цена выбранной монеты.

Дальше сетка панелей, которая переносится при сужении окна. Первый ряд: «Оценки» (`flex: 1 1 420px`) и «Рынок» (`flex: 2 1 560px`, график 760×280). Второй ряд: «Расписание», «Финансы», «Заметки» по `flex: 1 1 340px`. Панели стыкуются рамкой 1 px. Внизу строка подвала с пометкой про демо-данные. Ниже 900 px боковая панель превращается в нижнюю навигацию, а панели становятся отдельными экранами.

## Функции по разделам

В каждом разделе должно работать добавление, правка, удаление и пустое состояние. Удаление без диалогов: запись исчезает, внизу на 5 секунд появляется квадратная строка «ОТМЕНИТЬ».

### Оценки

- Предметы: создать, переименовать, архивировать.
- Оценка: значение (шкала 1–10 по умолчанию, в настройках можно выбрать 1–5 или 1–12), дата, вес от 1 до 3, комментарий.
- Средний балл по предмету и общий, взвешенный. Расчёт вынеси в чистую функцию с тестами.
- Быстрое добавление: нажатие на предмет раскрывает ряд кнопок 1–10, одно касание записывает оценку с сегодняшней датой.
- Динамика: мини-график среднего балла по неделям (ломаная SVG) на экране предмета.

### Финансы

- Операция: сумма, тип (доход или расход), категория, дата, заметка. Шесть категорий по умолчанию, список редактируется.
- Баланс = стартовый баланс из настроек + доходы − расходы. Символ валюты берётся из настроек.
- Столбики расходов по дням, переключатель «НЕДЕЛЯ / МЕСЯЦ».
- Фильтр списка по категории и периоду.
- Повторяющиеся операции (подписка, проезд): раз в неделю или месяц, создаются автоматически при открытии приложения.

### Расписание

- Неделя из шести дней. Урок: время начала и конца, предмет из списка предметов, кабинет, заметка. Переключатель чётной и нечётной недели (по умолчанию выключен).
- При открытии выбран сегодняшний день, в воскресенье выбран понедельник.
- Текущий урок помечается лаймовым индексом, рядом обратный отсчёт до конца урока или перемены.
- Копирование дня в другой день одним действием.

### Заметки

- Заголовок, текст (простой текст с переносами строк, без редактора разметки), тег, закрепление, необязательная привязка к предмету.
- Поиск по заголовку и тексту, фильтр по тегу, закреплённые всегда сверху.
- Автосохранение через 400 мс после ввода, кнопки «Сохранить» нет.

### Рынок

- Список наблюдаемых монет (по умолчанию BTC, ETH, SOL), до 10 штук, добавление через поиск по названию.
- Цена в USD, изменение за 24 часа, график за 1, 7 и 30 дней.
- Источник: публичный API CoinGecko (подробности в разделе про данные). Без сети или при ошибке показывай последние сохранённые значения с пометкой времени («ОБНОВЛЕНО 14:20») и не ломай интерфейс.
- Обновление раз в 60 секунд, пока вкладка открыта и видна.

### Настройки

Открываются из шапки: на телефоне кнопка «НАСТР.» рядом с датой, на ПК пункт внизу боковой панели. Внутри: шкала оценок, валюта, стартовый баланс, чётность недели, экспорт и импорт данных в JSON, кнопка «Добавить демо-данные», кнопка «Удалить всё» с подтверждением вводом слова УДАЛИТЬ.

## Данные и PWA

Всё хранится в IndexedDB через Dexie, приложение целиком работает без сети, кроме обновления котировок.

### Модель данных

```ts
Subject  { id, name, archived }
Grade    { id, subjectId, value, weight, date, comment? }
Txn      { id, kind: 'in' | 'out', amount, category, date, note?, repeat?: 'week' | 'month' }
Lesson   { id, day: 0..5, start: 'HH:MM', end: 'HH:MM', subjectId, room?, week?: 'even' | 'odd' }
Note     { id, title, body, tag?, pinned, subjectId?, updatedAt }
Watch    { coinId, order }
Task     { id, title, due, subjectId?, done }
Settings { gradeScale, currency, startBalance, weekParity }
```

id создавай через `crypto.randomUUID()`, даты храни строками `YYYY-MM-DD`. Суммы храни целым числом в минимальных единицах (центы, копейки), чтобы не копились ошибки дробей. У схемы Dexie есть номер версии и миграции. Экспорт: один JSON со всеми таблицами и полем `version`. Импорт проверяет версию и спрашивает «заменить» или «объединить».

### PWA

- `manifest.webmanifest`: имя и короткое имя «Трекер», `display: standalone`, `lang: ru`, `theme_color` и `background_color` `#101110`. Иконки 192, 512 и maskable 512: квадрат `#101110` с лаймовым квадратом по центру, без скруглений, для maskable лаймовый квадрат внутри безопасной зоны 80%.
- Service worker через vite-plugin-pwa. Оболочка (JS, CSS, шрифты, иконки) кэшируется целиком. Запросы к API котировок идут по стратегии «сеть сначала» с таймаутом 4 секунды и откатом на кэш.
- При выходе новой версии внизу появляется квадратная строка «ДОСТУПНО ОБНОВЛЕНИЕ» с кнопкой «ОБНОВИТЬ».
- Установка: слушай `beforeinstallprompt` и показывай пункт «УСТАНОВИТЬ» в настройках. На iOS показывай подсказку про «Поделиться → На экран Домой».
- При первом добавлении данных вызови `navigator.storage.persist()`.
- Проверка перед сдачей: Lighthouse Accessibility и Best Practices не ниже 95, установку и офлайн-режим проверь вручную в DevTools.

### Котировки

- Источник: публичное API CoinGecko, список с ценой и изменением за 24 часа (`/coins/markets`) и ряд цен за период (`/coins/{id}/market_chart?vs_currency=usd&days=1|7|30`). Перед реализацией сверься с актуальной документацией и лимитами. Ключи в клиентский код не клади.
- Ответы кэшируй в Dexie с меткой времени. Не чаще одного запроса на монету в 60 секунд. При ответе 429 увеличивай паузу и показывай последнюю цену.
- Для графика сократи ряд до 60–120 точек и масштабируй по минимуму и максимуму периода с отступом. Рисуй ломаную `polyline`, без сглаживания.
- Для разработки и тестов сделай файл с демо-рядами, он подключается при `VITE_DEMO_MARKET=1`.

## Порядок работы и критерии готовности

Начни с этапа 1. Перед кодом выведи план из 5–7 строк и сразу приступай, ответа не жди. Этапы по порядку:

1. Каркас и дизайн-система: Vite, TypeScript, токены, шрифты, базовые компоненты, оболочка с навигацией для телефона и ПК, хэш-роутер. Результат: пять пустых экранов переключаются, раскладки совпадают с разделом «Экраны».
2. Четыре раздела на локальных данных: оценки, финансы, расписание, заметки, а также «Обзор» и настройки. Схема Dexie, добавление, правка, удаление, пустые состояния, расчёты с тестами.
3. Рынок и PWA: котировки с кэшем и обработкой ошибок, манифест, service worker, установка, обновление, офлайн.
